# Campus Facility Overload Prediction using ARIMA

A Python + Streamlit prototype that forecasts hourly occupancy for campus facilities and flags likely overload periods.

## 1. Project status and data honesty

The included dataset is **synthetic demonstration data** generated by `generate_data.py`. It is not collected from a real university. Replace it with measured campus occupancy before claiming real-world predictive performance.

## 2. Setup (Windows PowerShell)

```powershell
cd campus_overload_arima
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python generate_data.py
```

If your machine has Python 3.10, use `py -3.10 -m venv .venv`.

## 3. Train and evaluate

```powershell
python train_model.py
```

Optional parameters:

```powershell
python train_model.py --horizon 24 --test-hours 48 --order 2 1 2
```

Outputs:
- `outputs/model_metrics.csv`: MAE and RMSE for each facility.
- `outputs/future_forecasts.csv`: next-horizon occupancy forecasts.

## 4. Run the dashboard

```powershell
streamlit run app.py
```

Open the local URL printed in the terminal, usually http://localhost:8501.

## 5. Uploading real data

The dashboard accepts a CSV with exactly these required column names:

| Column | Meaning | Example |
|---|---|---|
| timestamp | Date and time of observation | 2026-11-03 09:00:00 |
| facility | Facility name | Library |
| occupancy | Observed number of people | 83 |
| capacity | Maximum safe/operational capacity | 150 |

Recommended collection interval: 15 or 60 minutes. Use a consistent timezone and avoid mixing manual estimates with sensor counts without documenting the method.

## 6. Methodology

1. Sort observations chronologically.
2. Resample occupancy to hourly averages.
3. Split the latest observations into a chronological holdout set.
4. Fit ARIMA(p,d,q) on earlier observations.
5. Forecast the holdout period and calculate MAE and RMSE.
6. Refit on all available observations.
7. Forecast the next 24 hours.
8. Compare predictions with a configurable percentage of facility capacity.

ARIMA(p,d,q):
- p: autoregressive order, number of lagged observations.
- d: degree of differencing used to make the series more stationary.
- q: moving-average order, number of lagged forecast errors.

MAE = mean absolute error. RMSE = square root of mean squared error. Lower values are better, but compare them with the typical occupancy level and against a simple baseline (e.g., last-hour or same-hour-yesterday).

## 7. Important limitations and next improvements

- Standard ARIMA is univariate and does not directly use class timetables, holidays, weather, or events.
- Hourly occupancy has daily/weekly seasonality. Compare ARIMA with seasonal ARIMA (SARIMA) and a seasonal-naive baseline.
- The current prototype uses one model per facility, not one shared model.
- Forecast uncertainty increases with the forecast horizon.
- An alert threshold such as 90% is a configurable operational assumption, not a universal safety standard.
- Evaluate on multiple rolling time splits before making deployment claims.
